# ADR 0044: fence optional callbacks during UI transactions

- Status: M3-20 repair candidate; AE2023 qualification remains open.

The owner confirms native84/CEP86 performance improvement, but reports batch
deletion failure, occasional successful deletion with an AE stream identity
dialog, and Motion expected mode1 / saved0. Native84's passive log contains2,198
frames with no non-cancel render errors. The latest saved graph has two new
Motion nodes stored as Core Light Path0 / native popup2. Neither source proves
which UI callback caused the dialog or why those modes changed.

DRAW metadata refresh currently opens SDK state/streams during renderer guards1
and2. Delayed source supervision can likewise open a stale effect reference
before checking the renderer transaction. These are confirmed code gaps.

Extend the existing private resident-Host exclusion seam with a read-only query.
Optional DRAW metadata and source automatic publication return before SDK access
while the UI transaction/modal scope is held. DRAW also requires a delivered
renderer guard0; guarded/missing deliveries defer optimization to a later idle.
Source guard3 is valid retirement state and suppresses publication. Keep explicit
graph commit/finalization authoritative; do not revive withdrawn CRC schemes or
change timeouts. Public IDs, sequence/binding schemas and Core ABI9 stay fixed.
Optional synchronous metadata capture also defers while the Host exclusion is
held; the existing idle recertification resumes after physical cleanup.

Motion authors use the scalar mode record value, with explicit Core/native popup
mapping and immediate readback. Speed writes select Circle/Light Path using that
value instead of converting the entire record object to NaN. Offline fixtures
must cover complete three-mode native author/readback and structural invalidation;
they cannot establish that every reported AE failure is repaired.

The single native Speed stream has two Core representations: radians/second
(key4) and percent (key17). Panel edits update both, so strict saved-record
verification compares realizable records. For negative Circle speed, inactive
Path speed is zero, preserving Path's existing nonnegative range. Switching to
Path uses that nonnegative source. Motion/Turbulence curve comparison uses
decoded float tolerance, like Particle/Force, instead of comparing packed bytes.
