# 反馈问题

清晰的反馈能帮助判断问题发生在哪个环节。先保留原始工程和错误信息，不必为了描述问题反复改动唯一副本。

## 说明你想得到什么

写明预期结果和实际现象。例如“想让这组粒子变大，但调整后另一组发生了变化”，比只写“参数有问题”更容易理解。

## 记录使用环境

提供 Starfield 版本、After Effects 版本和操作系统信息。如果只有某个工程或素材出现问题，也一并说明。不要把能打开面板当成渲染已经正常的证明。

## 给出最短复现过程

说明从什么状态开始、依次做了什么、在哪一步出现提示。截图尽量同时包含相关节点关系和参数；有错误文字时，保留完整内容。可在简单工程中尝试缩小问题，但先保留原始文件。

## 分享前检查

如果需要提供工程，先移除无关内容，检查是否包含个人信息、商业素材或不便公开的文件。只分享有权提供的内容，不需要为一般反馈提交整个工作目录。

反馈入口可从官网的 GitHub 项目进入。更多定位思路见[遇到问题时](/help/troubleshooting)。
