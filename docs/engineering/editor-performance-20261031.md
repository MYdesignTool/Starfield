# PERF-10：编辑确认与布局保存

2026-10-31，Owner确认部署126/114删除故障已修复，但删除与编辑仍慢。本批以这套原生实现为稳定基线，仅改面板/gateway；保留单击编辑。原生11文件、Clear生命周期、绑定、Core、公开ID/schema均不改。

| 操作 | 已确认的额外成本 | 本批处理 |
| --- | --- | --- |
| 拖动画布中的节点位置 | moveNodes进入整图事务、作者manifest、发布与成功快照 | 手势只改本地位置，绘制按帧合并；停手600ms合并变化节点，单次写既有layout参数，不编译、不发布、不读全图 |
| 一段连续拖动 | 每次手势都独立保存全部坐标 | 未发送位置合并为最新值；后续手势暂停未发送的保存；结构编辑/失焦时冲刷已有队列 |

布局写入仍验证工程路径、目标、UUID唯一性、renderer/node空闲guard、非动画layout字段及旧坐标冲突；预检全部字段后只写变化轴。失败反向补偿已尝试字段，包括抛错前可能已写入的字段；Undo关闭/补偿失败准确报告。布局不占用全图pending，不重试未知回执，不清guard，也不改变saved graph revision/CRC。位置保存在既有AE普通参数，后续真实图提交会更新可选图布局记录。未提交的600ms本地队列须先保存才进入工程；切换AE焦点会主动冲刷，关闭面板的异步回调不提供额外持久化保证。

作者recordStamp包含位置，保持其现有不透明契约，不猜测重算浮点CRC。轻量保存成功只标记规划快照过期：下一次add/connect等manifest编辑先冲刷队列、只读一份当前快照再规划；native126删除只需既有saved revision/CRC，等待坐标保存后仍沿原入口，删除后保留一次必要的展示快照。跨目标/工程或保存失败不自动进入初始化、修图、清锁。

相同生产gateway与同一2作者节点DOM夹具对照：114完整getPanelState共259次标量value读取，115为164次，减少95次（约36.7%），两者原生作者读取均139次。115合并帧状态并用成功snapshot播种pulse；114时间变化改变结构stamp，115不改变。此处是调用量，不是AE耗时或大图线性估计。可复现工具及JSON：artifacts/perf-10-20261031/measure-read-budget.cjs、read-budget.json。

仍需后续分析的成本：删除后展示快照会读取所有作者参数与曲线；AE参数编辑仍要正确更新派生图及依赖；新增/连接的完整manifest和真正Model资产/动画回滚事务有其成本。本批不靠删掉新绑定验证、未知失败保护或资源回滚来提速。可以另卡研究局部显示快照、作者值缓存失效及增量参数发布，但必须保留动画/Undo/外部ECW编辑语义。

离线覆盖实际面板100次pointermove、一次坐标保存、后续manifest刷新保留位置、原生删除单次回执快照；队列覆盖连续合并、在途回退原点、串行flush、迟到回执与超时不重试；实际gateway覆盖双轴预算、无作者曲线读取、冲突/动画/guard拒绝及部分写入补偿。AE端耗时、真实Undo/重开和连续编辑手感由Owner验证，不能用VM运行时间代替。

第一位独立审校复现上述Undo旧顺序，以及固定comp.time改Time(Seconds)令作者stamp变化、pulse结构stamp不变。修前冻结/失败探针保留在artifacts/perf-10-20261031/reviewer-v1；已补历史barrier/ACK刷新、pulse独立authorTimeSeconds标记规划过期，并交另一位全新审校。外部AE菜单历史操作保持既有focus/周期审计，不承诺在其他控件历史命令前拦截所有宿主入口。

第二位新审校复现：layout-only Undo的host快照恰等于旧缓存时，reusable路径未重投影本地位置，下一次拖动CAS基线错误；父提出的大坐标相对容差也经独立实证，1e8坐标的5像素移动被误作no-op。已令dirty布局的host采用强制重投影、CAS容差固定为0.001像素，补Undo后再拖动及正负大坐标写入/冲突回归。v2修前快照/失败证据保留，最终候选再交全新v3审校。

第三位新审校确认上述修正，并独立复现旧在途ACK能在新拖动期间重启600ms保存。队列现用持续paused状态约束自动调度和发送；只有resume结束手势或显式结构/历史flush才放行。补held ACK→后续手势暂停→最新位置发送回归；v3反例保留，最终由全新v4复核。

第四位新审校确认既有修正，但复现写入前失败/完全补偿后host快照等于旧缓存时，本地未保存位置未重投影。布局一旦入队且有实际工作就标记需重新采用host，不等成功ACK才标记；这样成功、未知和拒绝均走相同的host重投影基线。补拒绝→刷新→下一次用户拖动回归，v4修前证据保留，再交全新v5复核。

第五位新审校确认既有反例修正，并实证较早保存的未知ACK在较新拖动中返回时，旧代码会丢弃活跃手势中的读取、却在mouseup继续从未知基线排队，CAS会拒绝并多读一次。Graph布局保存/手势增加topologyReady准入；活跃手势中失败先保留错误，不开无用读取；手势结束只读恢复host后再允许下一次用户保存。失败后没有新用户重试动作时不会自动排队第二次写入。v5证据保留，最终交全新v6审校。
