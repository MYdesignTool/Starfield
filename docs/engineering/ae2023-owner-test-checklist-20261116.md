## 第一轮：先确认原问题与最基本的MFR（A01、A02、M01～M03）

A01/A02已按你对前两项原问题的确认记为通过，本轮从M01做起。保留下面两项步骤作为历史回归说明，不要求再次执行。

### A01 新增效果的第一帧、画布和真实预览

1. 在新合成的新纯色层上新增 Starfield，节点面板的自动刷新保持开启。
2. 从点击新增前开始录一小段屏幕，包含节点画布和合成预览；等待初始化完成，再拖动时间线。
3. 删除效果并 Undo/Redo；在另一新图层再添加一次。
4. 稳定后手动添加 Force，修改一个能明显改变运动的参数，等待几秒并继续预览。

**通过标准：**全新效果直接采用 Emitter → Particle → Output 的默认结果；实际合成预览不短暂套上 Force 再被覆盖，节点布局不先显示旧四节点图。你明确添加的 Force 应保留并持续生效，不被迟到的初始化覆盖。若仍闪变，请保留视频并注明“只变画布”还是“真实粒子运动也变”。

### A02 冷启动直接打开工程

1. 由你正常退出 AE，再启动 AE，直接打开含 Starfield 的工程副本；先不要运行其他脚本或打开其他扩展来预热。
2. 打开 Starfield 节点面板，先无选择，再选中带效果的层；尝试 Refresh。
3. 打开预设面板，读取/应用一个预设；在使用 Model 的副本中再试一次已有 Model 的读取/编辑。
4. 正常退出后再做一轮；如方便，使用包含中文路径/名称的副本。

**通过标准：**不再出现 `[SF-P999] host_script_failed ... JSON is undefined`；无选择时正常显示提示，选中后能加载；真实其他错误应正常显示具体原因，不能只剩无信息空白或无限等待。首次启动仍失败、随后成功也算未通过，记录第一次的完整错误详情。

### M01 MFR标志和节点模块配对（必须132）

1. 确认使用132实验配对，在首选项找到 `Enable Multi-Frame Rendering` 并开启；记下原设置，测试后由你恢复。
2. 在干净测试合成中添加 Starfield，查看主效果是否仍有“不支持/未优化多帧渲染”的警告。
3. 通过节点编辑器逐类加入 Emitter、Particle、Force、Transform、Model、Material、Motion、Turbulence。只用现有合法连接和最简单可运行配置。
4. 若有警告，截下具体效果/节点名称。其他第三方效果的警告单独记录。

**通过标准：**九种 Starfield 效果不再因缺少 MFR 声明产生该警告，也不出现 `global outflags mismatch`、效果缺失或未知参数。警告消失只是入口检查，还需 M02/M03 确认输出和实际并行。

### M02 CPU串行/MFR同帧输出

1. 使用同一个固定工程副本：先仅 Emitter → Particle → Output，固定随机种子，做约4秒的连续动画。再加一段发射率关键帧。
2. 插件 Acceleration 设 CPU，工程使用软件渲染；先关闭 MFR 导出，再开启 MFR 导出，选择相同帧段、分辨率、质量、色彩和输出设置。
3. 两次输出分别保存到 `serial` 和 `mfr` 目录，不覆盖；先用8bpc无损序列。
4. 播放和跳帧查看；有差别时记下第一张不同帧的帧号。保留两份输出，我来做逐像素比较。

**通过标准：**同一路径同一帧的粒子数量、出生时间、位置、透明度与颜色一致，没有随机跳变、缺帧、黑帧、旧帧或崩溃。肉眼相同先记“外观通过，像素比较待核对”，不能据此宣称逐字节相同。

### M03 确认AE真的同时处理多帧

1. 用有一定计算量的连续帧段开启 MFR 预览和渲染队列导出，记录渲染界面的同时处理帧数，并保存一小段视频或截图。
2. 确认本次确有新渲染。若全部命中已有缓存，记为“未验证并行”，不要拿它判断速度或并发；如需清理内存预览缓存，由你在 AE 内明确操作，不操作磁盘缓存文件夹。
3. 测试结束保留 checkout 下 `artifacts/graph-render-journal-132.jsonl`，不用手改或删除内容。

**通过标准：**能够得到实际 Starfield render 回调在不同线程、不同帧上的重叠证据。界面、CPU占用和警告消失可辅助观察，最终我结合日志核对。GPU很快、CPU较少或内存不足导致AE仅分配一帧时，记“未观察到”，不冒认已验证或插件必然有错。
